# ridecast

ridecast (route weather): a motorcycle-focused web app that shows weather, risks and warnings along a route, based on the time you reach each point. English UI with a Turkish option, map-first layout that works like a phone app (bottom sheet on phones, floating card on desktop), system light and dark themes.

Live: https://kaandinc.com/ridecast/ (GitHub Pages, deployed by `.github/workflows/pages.yml` on every push to `main`).

## Setup

Requires Node 22+.

```
npm install
npm run dev      # dev server
npm run build    # type check + production build
npm run test     # Vitest (src/core)
```

The build uses relative asset paths (`base: "./"` in `vite.config.ts`), so `dist` works from any sub-path.

## Usage

- Language: English by default; the EN / TR switch in the panel header changes every text (warnings, clothing, dates, errors) to Turkish and back. The choice is kept in the browser and the page reloads with the same trip. Texts live in `src/i18n/en.ts` and `tr.ts` (same shape, checked by TypeScript); core code gets its warning and clothing texts passed in. Test notes below from before stage 24 quote the Turkish labels of that time.

- Type an address in Start / Destination and pick a suggestion (Photon, as you type, biased to the map centre); arrow keys move through the suggestions and Enter takes the first or the focused one.
- Directions work like Google Maps: "Add stop" appends a new destination (the old one becomes a via stop); drag a stop's glyph in the card (or focus it and press the arrow keys) to reorder; with two stops a swap button reverses the trip, with more every row has a remove button. Empty rows are skipped when routing.
- Panel (Google Maps style): the app opens on the bare map with only a compact search bar (the destination field). Tapping it opens the full panel. The back arrow in the panel header clears the trip (stops, route, breaks, weather, share link) and returns to the compact bar; settings and the map view stay. With a route, the collapsed panel keeps its peek height on phones and stays open on desktop.
- Map: clicking an empty spot drops a pin with a place card (address from Nominatim, coordinates, "From here", "To here", "Add stop"). Right click (long press on a phone) opens a menu: coordinates (click to copy), "Directions from here", "Directions to here", "Add stop", "Add a break here" (snapped to the selected route), "What's here?". Stop pins can be dragged to a new place; the route and label follow.
- Every route has a duration bubble placed where it leaves the other routes (`labelPoint` in `core/route/line.ts`); clicking an alternative's bubble or line selects it.
- Map tools: drag a route line with the mouse to drop a via stop where you release it (it goes before the next stop along that route). "Layers" (top right) switches the base map between Map (muted OSM), Satellite (Esri World Imagery) and Terrain (OpenTopoMap), and toggles "Rain radar" (latest RainViewer frame, time shown); the choice is remembered in the browser. Bottom right: "Show my location" (centres on the device and shows a dot, tapping it opens the place card; with no start set it also becomes the start), zoom buttons (hidden on phones, pinch instead) and a metric scale. "Measure distance" in the right-click menu starts a ruler: clicks add points, points drag, clicking a point removes it, the card shows the total. Shortcuts: Escape closes the menu, the place card and the ruler; "/" jumps to the next empty address field.
- The route is fetched as soon as start and end are set. Alternatives are drawn in grey; click one on the map or in the panel to select it.
- Vehicle: motorcycle (default), car, bicycle, walking. Changing it resets the speeds to that vehicle's defaults (`src/config/vehicles.ts`) and routes again with that vehicle's profile: motorcycle and car on the OSRM demo server, bicycle and walking on the FOSSGIS OSRM bike and foot profiles (routing.openstreetmap.de).
- Route options (like Google Maps' route options): "Avoid motorways", "Avoid tolls" (motor vehicles) and "Avoid ferries" (all). The public OSRM servers reject exclude flags, so a trip with any of them is routed by Valhalla (FOSSGIS server, costing motorcycle / auto / bicycle / pedestrian with `use_highways`, `use_tolls`, `use_ferry` = 0); its maneuvers become the steps, and their street names carry the O-/D- refs for the road type guess. The options are part of the share link (`av=htf`).
- Speed: one average speed, or "By road type" with separate motorway / main road / urban speeds. All values are editable (1-250 km/h).
- Departure: now, or a date and time. The panel shows total time, departure, the arrival at each via stop and at the end, and in road mode the km per guessed road type.
- Weather: the selected route is sampled about every 15 min of driving (at most 30 points, start and end included). Each point shows the forecast hour nearest to your arrival there, as a capsule on the map (thinned out when zoomed out) and in the "Weather along the route" strip. Tapping either opens a card: arrival time, km, temperature and feels-like, condition, precipitation (mm and %), snow, wind speed, direction and gusts, visibility, and which forecast hour was used. Night hours show a moon.
- Risks: every weather point gets a level (none, low, medium, high) from the vehicle's thresholds in `src/config/risk.ts`: storm, snow, crosswind (the part of the gusts across the direction of travel and the side it comes from; motorcycles from 25 / 40 / 55 km/h, bicycles 20 / 30 / 45, cars 45 / 60 / 80, none on foot; when it is at least as serious as the plain gust warning it takes its place, so one wind gives one row), rain (with Open-Meteo's precipitation probability in the text; a probability of 60% or more alone is a low warning for motorcycles and bicycles, 70% on foot, never for cars: `rainProbPct`), gusts, fog and visibility, ice and near-freezing temperature, cold as felt while riding (wind chill from riding speed plus the headwind part of the wind), a wet road estimate from rain now and in the last 3 hours (labelled "estimate"), and riding in the dark (from Open-Meteo sunrise and sunset). Two more since stage 19: sun glare, when the sun is up but at most 15° high, within 30° of the direction of travel and the sky is clear to partly cloudy (sun position from the NOAA solar equations in `core/risk/sun.ts`, `GLARE` in config; medium for motorcycles and cars, low for bicycles); and heat stress from the apparent temperature (humidity and wind included), 30 / 35 / 40° for riders (gear traps heat), 32 / 37 / 41° on foot, none in a car, with "rest in the shade and drink" from medium up. The selected route is coloured by level, dark parts get a dotted pattern, capsules get a coloured ring, and the "Warnings" list merges consecutive points into one row with time and km range. Tapping a row opens that point.
- Best time: the third departure option compares every full hour in the next 24 hours for the selected route (with its speed and breaks) and lists the 3 with the lowest risk score, with arrival time and score; equal scores go to the earlier departure, and the three are at least 2 hours apart (`minGapH`), so the list is three real choices instead of 08:00, 09:00, 10:00. The first one is taken automatically; tapping another re-plans the route for that time. All candidates are scored from the same forecast request as the normal view (`src/config/departure.ts`).
- Best day: the "Best time" panel switches between "Next 24 h" (above) and "Next 7 days", which scores every full hour of the next 7 days the same way (one forecast request reaching 7 days plus the trip) and lists the best departure of each calendar day; days more than 3 days ahead are dashed as uncertain. Tapping a day re-plans for it.
- Safest route: every route option gets its own forecast (one request per route) and a risk score: the mean of 0 / 1 / 3 / 9 for none / low / medium / high along the route (`RISK_WEIGHTS`), weighted by riding time (each point's stretch divided by the speed there, breaks left out), so a slow stretch in the rain counts more than a fast one of the same length. The card shows the score and the worst level. The lowest score is marked "Safest route" with its time and risk difference against the fastest route ("+29 min, 92% less risk"), but only if it is at least 10% lower (`SAFEST_MIN_DROP`); otherwise the fastest keeps the mark ("Also the fastest"). No mark when no route has any risk.
- What to wear: a fixed rule table (`src/config/clothing.ts`) checked against the worst conditions on the selected route: lowest felt temperature, highest temperature, rain or a wet road, gusts, lowest visibility, darkness, snow or ice. Each item says why ("lowest felt -1°"); an item from two rules shows once with both reasons. Rules are per vehicle, so a car gets far fewer items.
- Fuel and rest stops: on request ("Show fuel and rest stops") one Overpass query asks for fuel stations, motorway services and rest areas in one bounding box per ~20 km of the selected route; stops more than 1 km from the route are dropped. Of each kind at most one stop per 10 km is listed, with km and ETA. Where the route has rain, snow, a storm or a felt temperature of 5° or less, only sheltered stops are shown (fuel canopies, services; rest areas only if tagged with a shelter, shop or building) and they are marked in blue. Each stop, in the list or its map popup, can be added as a break.
- Fuel range: an optional tank range (km, under Route options). When it is set, the route's fuel stops are loaded once (the same Overpass query as "Show fuel and rest stops"; fuel stations and motorway services within 1 km of the route, before any thinning), and every stretch longer than the range between two places to fill up (the start with a full tank, each station, the arrival) becomes a medium warning with its km range, times and the last station before it ("No fuel for 180 km (range 150 km) · fill up at …"). The range is part of the share link (`fr=`).
- Live mode: "Start ride" follows the phone's GPS (`watchPosition`) on the selected route and switches to a large glance view: the next warning ahead with its distance and time, time and km left with the arrival, and the weather at the next point. ETAs are re-anchored at the rider's position and pace (planned time for the last 15 min of riding divided by the real time, clamped to 0.5-1.6); arrival times, weather points and warnings follow. The forecast is fetched fresh every 12 min (or with "Refresh weather now"). A warning ahead that is new or got worse since the last forecast raises a banner and vibrates (and beeps when "Ses" is on); the first forecast of a route only sets the baseline, and a warning is only news once per route unless it gets worse. After 3 fixes in a row more than 150 m from the route (and further than the GPS accuracy allows), "Plan again from here" plans again from the current position to the stops and breaks still ahead. The screen is kept on with the Screen Wake Lock API, taken again when the page comes back; without it a note says the screen may turn off. "Map" shrinks the view to a pill over the map that follows the position; "End" stops tracking. "Sun" switches the glance view to black on white with darker risk colours, bolder secondary text and thicker rings for reading in sunlight; it starts on when the system asks for more contrast, and the choice is remembered.
- Sharing: the whole trip lives in the URL hash and is kept up to date while you edit: stops (coordinates and a short label), breaks with their minutes, vehicle, speed mode and values, departure (now, a fixed time, or best), and the selected route. "Copy link" copies it; if the clipboard is blocked or does not answer within 1.5 s, the link appears selected in a field instead. Opening the link restores everything and fetches route and weather again. A broken link shows "This link could not be read" and keeps the current trip.
- Recent routes: each planned trip is saved in the browser (localStorage, last 6, the same stops replace their older entry) and listed as "Recent routes" while no route is open. Without browser storage the app works the same, only without the list.
- GPX: "Open a GPX file" reads a track (or, without one, a route) from a .gpx file and uses it as the route itself, so a curvy route planned elsewhere (Kurviger, Calimoto) gets ETAs, weather, risks, breaks and live mode; its two ends become the stops (with reverse-geocoded labels). The file has no road data, so the road type guess treats it as main road (`GPX_TRACK_KMH`). Editing a stop routes normally again. "Save GPX" saves the selected route as a GPX 1.1 track with the stops and breaks (minutes and start time) as waypoints. Parsing and writing are plain text functions in `core/route/gpx.ts`, no DOM.
- Calendar: "Add to calendar" saves an iCalendar file (RFC 5545: CRLF lines folded at 75 octets, escaped text, UTC times) with one event per riding day (overnight stops split days); each event lists that day's breaks, the weather warnings that start that day plus the break and fuel ones, and the plan link. Built by `toIcs` in `core/share/ics.ts`.
- Install and offline: the page has a web manifest and icons (`public/`), so a phone can add it to the home screen as a standalone app. A hand-written service worker (`public/sw.js`, production build only) caches the app shell at install (index.html and every file it links) and keeps the last 40 routing (OSRM, FOSSGIS, Valhalla) and Open-Meteo responses, network first with the cached copy as the fallback: reopening a trip without signal shows its route and weather. While riding, a failed forecast refresh keeps the last forecast on screen; the live view and the planner say "Offline", and the forecast is fetched again as soon as the connection is back. Map tiles are not cached by the worker (tile policies forbid prefetching), only by the browser's normal cache.
- Multi-day tours: "Stay overnight" on a break turns it into an overnight stop: instead of minutes it has a "ride on at" time (08:00 by default), and the trip goes on at the first such local time at least 4 hours after arriving (`OVERNIGHT`). The summary then lists each day with its start, end and km, the break row shows arrival and departure with dates, and the link keeps it (`15n480`). Forecasts are fetched as far as the trip goes (Open-Meteo gives 16 days); points more than 3 days ahead (`farDays`) get a dashed tile in the strip and an "uncertain" line in their card.
- Since your last look: every forecast of a trip saves its warning runs (kind, level, km range, start time after departure) in the browser, for the last 10 trips (`CHANGES` in `config/share.ts`). When the same trip (same link) is opened again at least 10 minutes later, its first forecast is compared with the saved one (`diffWarnings` in `core/advice/changes.ts`): new warnings, ones that got stronger or weaker, ones that start at least 30 min or 10 km earlier or later ("Felt while riding 4°: starts 2 h 0 min earlier"), and ones that are gone, worst news first. Live mode does not compare (it has its own alerts).
- Break advice: if rain starts during a break, the break row says at which minute and suggests a shorter break; if it rains when the break ends and stops within 90 min, it suggests how long to extend it.
- Breaks: click the selected route to add a break there (snapped to the route, 15 min by default). Drag its marker along the route to move it, change its minutes (5/10/15/30/60 suggested, any 1-600 allowed) or remove it in the list. "Add automatic breaks" places breaks every N km or every N minutes of riding; running it again replaces the automatic breaks that were not edited. Each break shows its km and start/end time, and every later arrival moves by its duration.

## Layout

```
src/config/    vehicle defaults, road type rules (all tunable numbers)
src/core/      pure TypeScript, no DOM/fetch: coordinates, route geometry (snap, slice, bearing), road type guess, ETA timeline with breaks, weather sampling, forecast hour matching, WMO codes, risk levels, wind chill, wet road estimate, break advice
src/services/  Photon, Nominatim, OSRM, Open-Meteo, Overpass clients + in-memory request cache
src/ui/        Leaflet map and panels; app.ts holds the planner state and wiring, forecast.ts the forecast and risk per route, mapActions.ts the map click, menu, locate and shortcuts, gpx.ts the GPX buttons, and summary / best / share / stops / breaks / trip / changes render their panels
```

## Limits

- Map layers: Esri World Imagery and OpenTopoMap tiles are used keyless under their public terms with attribution; RainViewer radar only goes to zoom 7 and covers the countries its radar sources cover. There is no compass: Leaflet maps do not rotate, north is always up.
- Services are public demo/free servers, meant for light use only: OSRM demo server, Photon (address suggestions, 350 ms debounce; Nominatim's policy forbids client-side autocomplete), Nominatim (reverse lookup only, max 1 request/s, enforced client side with a queue), Overpass (on request only), Open-Meteo (free for non-commercial use), OSM tiles (attribution shown, no prefetching). The live copy is a personal portfolio demo; heavy use would need own servers.
- Motorcycles are routed with the car profile unless an avoid option is on (then Valhalla's motorcycle costing). Valhalla orders its routes by its own cost, so the first one is not always the fastest.
- OSRM returns alternatives only when there are exactly two stops.
- OSRM snaps any point to the nearest road (even across ferries), so "route not found" is rare.
- Road type is a guess: Turkish refs (O-x motorway, D-x main road) first, else the OSRM step average speed (>= 90 km/h motorway, >= 70 main road). Fast provincial roads without a ref can count as urban.
- Ferry steps keep the OSRM duration, whatever the vehicle speed.
- ETA uses constant speeds per road type; no traffic.
- Weather points are rounded to 0.05° (~5 km) so ETA-only changes reuse the cached forecast; the forecast is for that grid point, not the exact road.
- Open-Meteo covers about 15 days ahead. A request that takes longer than 15 s counts as failed (retry button).
- Day or night comes from Open-Meteo's is_day. Sunrise, sunset and dark-riding warnings come in stage 5.
- Live mode was tested with a simulated GPS, not on a real ride. On the web, GPS tracking is not reliable while the page is in the background or the screen is locked; the wake lock only keeps the screen on while the page is visible, and browsers can refuse it (battery saver).
- The pace uses route distance, so riding a detour parallel to the route counts as progress until the off-route check catches it; on routes that pass the same place twice, snapping can jump to the other pass.
- A trip from a GPX file shares only its start and end: the link routes between them again.
- Live mode re-times the rest of the trip by the rider's pace, overnight stops included, so a live ETA past an overnight stop is only rough.
- Links do not carry the weather or the stops found by Overpass; they are fetched again when the link is opened, so a shared link shows the forecast at the time it is opened. A link with departure "now" departs at opening time.
- Stop labels in links are shortened to their first two parts.
- Overpass is a shared public server: the stops query runs only on request and can take several seconds or fail when the server is busy (the message says so, the button stays for a retry).
- Shelter is guessed from OSM tags; a fuel station counts as covered.
- Best departure candidates are hourly and only for the selected route; the top 3 can be neighbouring hours when they tie.
- The route score is my own weighting. It compares routes by the share of distance at each level, not by time spent at each level.
- Risk levels are per sample point (about every 15 min of driving); a short shower between two points can be missed. Thresholds are my own starting values, not from a published standard, except the wind chill formula.
- Wind chill is only defined up to 10 °C; above that the felt temperature is the air temperature.
- Break advice uses the forecast of the sample point nearest to the break and hourly steps.
- Map tiles are OSM standard tiles muted with CSS filters; keyless muted basemaps (CARTO) now watermark browser requests. OSM tiles are for light use only.
- Breaks are stored as map points. On another route (alternative, or new stops) they snap to its nearest point, which can be far from where they were meant to be.
